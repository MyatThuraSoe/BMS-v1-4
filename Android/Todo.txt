📋 MASTER PROMPT: Solite-POS to LumiPOS Android Transformation
Role: Act as an Expert Android Architect and Senior Kotlin Developer specializing in Jetpack Compose, Clean Architecture, and offline-first applications.
Objective: Transform the existing open-source Solite-POS (Kotlin/Jetpack Compose) into a new, modernized Android application named LumiPOS. The new app must be 100% offline (no server/network connections required), feature a modern UI inspired by the web-based LumiPOS design, and be fully responsive across both mobile phones and tablets. All dependencies must be upgraded to their latest stable versions.

1. 🛠️ Target Tech Stack & Dependency Upgrades
Upgrade the project to the latest modern Android standards:
Language: Kotlin 2.0+ (with Kotlin DSL for Gradle).
UI Framework: Jetpack Compose (latest stable BOM), utilizing Material 3 for modern theming.
Architecture: MVVM + Clean Architecture (Domain, Data, Presentation layers).
Dependency Injection: Dagger Hilt (latest version).
Local Database: Room 2.6+ with Kotlin Coroutines & Flow.
Local Preferences: Jetpack DataStore (Preferences & Proto) replacing legacy SharedPreferences.
Navigation: Jetpack Compose Navigation 2.7+ with type-safe navigation.
Concurrency: Kotlin Coroutines 1.8+ & Flow.
Image Loading: Coil 2.6+ (for product images).
PDF/Export: iText7 or Apache POI (Android-compatible) for local receipt/data export.
Printing: Android Bluetooth Printing libraries (e.g., EscPosPrinter or native Bluetooth Socket).
Removed Dependencies: Completely remove Retrofit, OkHttp, Firebase (Crashlytics/Remote Config), and any cloud-sync logic to enforce the 100% offline mandate.

2. 🏗️ Architectural & Core Changes (Offline-First Mandate)
No Network Layer: Delete all Retrofit, API interfaces, and remote data sources.
Local-Only Authentication: Replace server-based login/register with a local User entity in Room. The first run should trigger a "Setup Local Admin" screen (PIN/Password). Subsequent logins validate against the local Room database.
Local Data Export/Import: Replace "Online Backup" with Local Backup/Restore. Allow users to export the entire database to a .json or .xlsx file in the device's local storage (e.g., Downloads/LumiPOS_Backup/), and import it back (with MERGE or REPLACE_ALL modes, inspired by web LumiPOS).
Device Binding: Remove multi-device cloud sync. If "Multiple Branches" are needed, they are managed as logical branches within the same local database, not synced across devices.


3. 📱 UI/UX & Responsive Design Requirements
The UI must mirror the clean, professional aesthetic of the web-based LumiPOS, but adapt fluidly to screen size.
Responsive Layouts: Use Compose WindowSizeClass (isCompact, isMedium, isExpanded) to dynamically change layouts:
Mobile (Compact): Single-column layouts, bottom navigation bar, stacked forms.
Tablet (Expanded): Dual-pane layouts (e.g., Master-Detail for Product Lists, side navigation rail instead of bottom nav, split-screen POS checkout).
Theming: Implement a modern Light/Dark mode Material 3 theme. Primary colors should align with LumiPOS branding (e.g., clean whites, soft grays, and a distinct primary accent color like deep blue or teal).
Touch Targets: Ensure all buttons and interactive elements meet Android's 48x48dp minimum touch target size for retail environments.
Typography: Use a clean, legible font (e.g., Inter or Roboto) with clear hierarchy for prices and totals.
